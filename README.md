# AqylMed AI

Помощник врача: запись приёма → расшифровка → разделение «врач / пациент» → **черновик медицинского
заключения и памятка пациенту** → проверка и подтверждение врачом.

Это реализация технического отчёта (этапы 1–4 и инфраструктурные требования пилота).
ИИ **не ставит диагнозы**: всё, что он создаёт, — черновик, который не считается документом, пока врач
его не проверил и не подтвердил.

```
Аудио / текст ─► STT (Groq Whisper | OpenAI) ─┐
                 диаризация (pyannote, опц.) ─┴► выравнивание ─► Gemini: роли + очистка
                                                                       │
        Памятка ◄─ Gemini: заключение ◄────────────────────────────────┘
           │             │
           ▼             ▼        автопроверка чисел/доз ─► предупреждения врачу
   ┌────── веб-интерфейс врача: правка · подтверждение · Word · печать ──────┐
   └── журнал действий · учёт расходов · сроки хранения аудио · роли ─────────┘
```

## Быстрый старт (локально)

```bash
python -m venv venv && source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt                       # + requirements-audio.txt для диаризации (torch)
cp .env.example .env                                  # заполнить DATABASE_URL, ключи, SECRET_KEY
alembic upgrade head                                  # создать/обновить таблицы
python -m app.cli create-user --email you@clinic.kz --name "Иванова А.К." --role admin
python -m app.cli check-config                        # проверит БД, ffmpeg, ключи, доступность модели
python -m app.cli serve                               # http://127.0.0.1:8000
```

Нужны: Python 3.12, PostgreSQL, **ffmpeg** (mp3/m4a/webm и сжатие записей).

### Docker

## ⚠ Что нужно сделать до первого запуска

1. **Смените модель Gemini.** `gemini-2.5-flash` из техотчёта по сообщениям Google выводится из эксплуатации
   **16.10.2026** (на момент подготовки проекта этот срок уже прошёл). Значение по умолчанию — `gemini-3.8-flash`.
   Актуальный список: <https://ai.google.dev/gemini-api/docs/deprecations>; `check-config` проверит, что ваша
   модель отвечает. Тарифы у новых моделей другие (см. «Расходы»). Промпты настраивались под 2.5 — после смены
   модели прогоните свои примеры и сравните результат.
2. **Отзовите и перевыпустите ключи**, которые лежали в архиве проекта: `GROQ_API_KEY`, `GEMINI_API_KEY`,
   `HF_TOKEN` (в `.env`) и пароль PostgreSQL (был в открытом виде в `alembic.ini`). Теперь Alembic берёт URL
   из `.env`, а `.env` в `.gitignore` — но ключи, попавшие в архив/чат/репозиторий, считаются скомпрометированными.
3. В production обязательны `SECRET_KEY` и `ENVIRONMENT=production` (иначе приложение не стартует).

## Возможности

| Из техотчёта | Реализовано |
|---|---|
| Этап 1 — текстовый прототип | `python -m app.cli generate` и веб-форма «Готовый текст». Исправлен сломанный вызов из этапа 1 |
| Этап 2 — аудио | Загрузка файла **и запись с микрофона** в браузере; STT → диаризация → выравнивание → роли |
| Этап 3 — backend/БД | FastAPI, PostgreSQL, Alembic (миграция сохраняет существующие данные), обработка ошибок, журналирование |
| Этап 4 — интерфейс врача | Список приёмов, просмотр расшифровки и прослушивание, редактирование, подтверждение, экспорт Word, печать |
| Сравнение STT-моделей | `python -m app.cli benchmark-stt` — время, цена, WER, доля найденных мед. терминов |
| Риск «выдуманные сведения / дозы» | Строгие промпты + **автопроверка**: числа с единицами (мг, мл, °C, мм рт. ст., %) должны быть в диалоге, иначе предупреждение |
| Риск «неверные роли» | Врач видит диалог с ролями, может поменять «Врач ↔ Пациент» и перегенерировать заключение |
| Пилот: доступ и права | Вход по паролю, роли врач/администратор, врач видит только свои приёмы, блокировка перебора пароля |
| Дополнительная защита | Опциональный `TWO_FACTOR_ENABLED=true`: одноразовый email-код при входе; сброс пароля по одноразовой ссылке |
| Мультиязычность | Русский/казахский/английский, автоматический выбор языка браузера и настройки пользователя; язык текста заключения определяется по речи |
| Медицинские справочники | Администратор ведёт специальности и шаблоны на трёх языках, импортирует клинический справочник МКБ-10 |
| Запись с микрофона | Пауза/продолжение без потери уже записанного аудио |
| Пилот: журнал | Кто/что/когда (просмотр, правка, подтверждение, экспорт, прослушивание, удаление). Содержимое записей и ФИО в журнал не пишутся |
| Пилот: сроки хранения | `AUDIO_RETENTION_DAYS`, удаление после обработки, ручное удаление, `purge-audio` |
| Пилот: контроль расходов | Учёт каждого вызова API, сводка по месяцам/моделям, **лимит** `MONTHLY_API_BUDGET_USD` |
| Пилот: устойчивость | Повторы при 429/5xx с нарастающей паузой, зависшие задачи помечаются при перезапуске, `/api/health` |
| Согласие пациента | Для аудио нельзя продолжить без отметки о согласии; факт отметки пишется в журнал |
| Оценка точности на пилоте | Хранится исходный черновик ИИ и итог врача — их можно сравнить |

## Настройка (`.env`)

Все параметры и комментарии — в [`.env.example`](.env.example). Главное:

* **`DIARIZATION_ENABLED=false`** — без torch/pyannote. Роли тогда определяет Gemini по смыслу реплик
  (дешевле и проще в развёртывании, но менее надёжно, чем диаризация по голосу).
* **`STT_PROVIDER=groq|openai`**. У `gpt-4o-transcribe` / `gpt-4o-mini-transcribe` **нет временных меток** сегментов.
  Если включена диаризация, запись режется по репликам и каждая распознаётся отдельно (точнее по ролям, но
  больше запросов; у Groq минимум оплаты 10 с на запрос). `whisper-1` и Whisper на Groq метки отдают.
* **`GROQ_STT_LANGUAGE`**: `ru` фиксирует русский; пустое значение — автоопределение (казахский/смешанная речь).
  Качество на казахском и смеси нужно проверить `benchmark-stt` на ваших записях.
* **`MAX_UPLOAD_MB`**: Groq принимает файлы до 100 МБ на платном тарифе (на бесплатном меньше). Записи
  приводятся к моно 16 кГц FLAC — 20 минут занимают порядка 10–20 МБ.

### Почта, языки и медицинские справочники

Для email-кодов 2FA, сброса пароля, уведомления об изменении пароля и подтверждения новых учётных
записей задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM_EMAIL` и при необходимости
`SMTP_USERNAME`/`SMTP_PASSWORD`. Включите `TWO_FACTOR_ENABLED=true` для OTP при входе и
`EMAIL_VERIFICATION_REQUIRED=true`, чтобы новые аккаунты, созданные администратором, подтверждали адрес.
Включите `EMAIL_NOTIFICATIONS_ENABLED=true`, чтобы отправлять уведомления о завершении/ошибке обработки
и об изменении пароля. Настройте
`PASSWORD_RESET_URL` на общедоступный адрес веб-приложения.

Интерфейс выбирает язык по `navigator.languages`; врач может переключить язык в верхней панели.
Оставьте `GROQ_STT_LANGUAGE` пустым для автоопределения языка речи. ИИ формирует черновик на языке
основной консультации. Медицинский текст и перевод всегда должны быть проверены врачом.

Клинические данные в проект не зашиты. В «Администрирование → Справочники» добавьте названия
специальностей и шаблоны из вашей клиники, затем импортируйте проверенный JSON-массив МКБ-10 со
свойствами `code`, `name_ru` и необязательными `name_kk`, `name_en`. Неполный черновик можно сохранить; подтверждение всегда требует действительного кода МКБ-10,
даже если справочник ещё пуст. ИИ не назначает код автоматически: врач выбирает его из справочника.

В панели «Справочники» есть выбор JSON-файла, предварительный просмотр содержимого и кнопка
«Скачать пример JSON». Специальности импортируются массивом `name_ru`, `name_kk`, `name_en`;
повторная загрузка обновляет запись по русскому названию. МКБ-10 обновляется по коду (до 100 000
записей за запрос, файл до 10 МБ). Примеры описывают формат и не заменяют полный классификатор.

Шаблон загружается объектом `locale`, `document_type`, `fields`. Поддерживаются `initial`
(первичный приём), `examination` (осмотр), `discharge` (выписка). `fields` задаёт подписи стандартных
разделов медицинского документа. Выберите специальность, язык и тип, загрузите JSON и сохраните.
В разделе «Пользователи» назначьте специальность врачу, включая существующие аккаунты.
При создании приёма выберите тип документа. Язык содержания определяется моделью по диалогу;
соответствующие подписи шаблона сохраняются в приёме и используются в карточке, Word и TXT.
Изменения справочника не меняют уже созданные документы; перегенерация использует актуальный шаблон.

После обновления выполните `alembic upgrade head` и перезапустите сервер. Существующие сессии
потребуют повторного входа: токены теперь привязаны к паролю и отзываются при его смене/сбросе.
Без SMTP вход по паролю работает, но отправка OTP, подтверждений и ссылок восстановления
требует настроенного почтового сервера. Реальные письма и распознавание требуют ваших SMTP/API-ключей.

## Сравнение моделей распознавания

```bash
python -m app.cli benchmark-stt -a examples_audio/consultation_01.wav \
   -m groq:whisper-large-v3 -m groq:whisper-large-v3-turbo \
   -m openai:gpt-4o-mini-transcribe -m openai:gpt-4o-transcribe \
   -r эталон.txt -t термины.txt
```
`эталон.txt` — ваша ручная расшифровка (для WER), `термины.txt` — препараты, дозы, числа по одному в строке.

## Расходы

Тарифы лежат в `app/core/config.py` и переопределяются в `.env` (`STT_PRICES_PER_MINUTE`, `LLM_PRICES_PER_MILLION`, JSON).

* Groq Whisper v3 — $0,111/час (= $0,00185/мин), Turbo — $0,04/час (≈ $0,00067/мин): совпадает с техотчётом.
* OpenAI-тарифы взяты из техотчёта и не перепроверялись.
* Gemini: `3.5-flash` ≈ $1,50 / $9,00 за 1 млн токенов (вход/выход), `3.5-flash-lite` ≈ $0,30 / $2,50,
  `3.1-flash-lite` ≈ $0,25 / $1,50 — **цифры из сторонних обзоров, сверьте с ai.google.dev**.
  Токены «рассуждений» считаются как выходные: реальная цена приёма может быть выше расчёта $0,008 из отчёта.
  Реальную стоимость приёма показывает вкладка «Расходы» (`python -m app.cli usage`).

## Что проверено, а что нет

Проверено автоматически: весь backend на SQLite **и на реальном PostgreSQL 16**; миграция на БД со старыми
данными (данные сохраняются, расхождений со схемой нет, откат работает); интерфейс в настоящем Chromium
(вход, создание приёма из текста и аудио, правка, подтверждение, Word, печать, защита от XSS, мобильная
вёрстка, админка).

**Не проверено — нет ключей и доступа к этим сервисам из тестовой среды:** реальные вызовы Gemini, Groq и OpenAI
(в тестах они подменены, но SDK-клиенты и объекты запросов создаются настоящими библиотеками);
работа pyannote/torch (код диаризации сохранён как был у вас); сборка Docker-образа. Перед пилотом прогоните
`check-config` и 3–5 своих записей по `from-audio`.

## Безопасность и данные

Сделано: пароли — scrypt; JWT с ограниченным сроком; блокировка перебора; изоляция данных между врачами;
заголовки CSP/nosniff/no-store; загрузки — белый список форматов, лимит размера, имена файлов только uuid;
речь пациента в промпт передаётся как данные (защита от «prompt injection»), в интерфейсе — только как текст;
внутренние ошибки врачу не показываются.

Остаётся на вашей стороне (отчёт справедливо выделяет это отдельным пунктом): правовое основание и согласия на
обработку, оценка требований законодательства РК о персональных данных и медицинской тайне **и трансграничной
передаче** (аудио и текст уходят к Groq / Google / OpenAI), договоры с поставщиками, шифрование диска и бэкапов,
резервное копирование с проверкой восстановления, HTTPS, мониторинг. Для разработки используйте обезличенные записи.

## Масштабирование

Фоновые задачи живут в памяти процесса — запускайте **один воркер uvicorn** (так и настроен Docker). Для нескольких
клиник замените `app/services/runner.py` на очередь (RQ/Celery): остальной код менять не нужно. Блокировка входа
тоже хранится в памяти процесса. Интеграции с МИС — вне текущего объёма.

### Удобство работы с приёмами

Список показывает по 25 приёмов с переходами между страницами, общим количеством и сбросом
фильтров. Устаревшие ответы поиска не заменяют результаты нового запроса.
В карточке работают Ctrl/Cmd+S и предупреждение при уходе с несохранёнными правками.
Word и печать сначала сохраняют текущие изменения; перегенерация требует подтверждения перед
заменой правок. Изменения, внесённые во время сохранения, остаются помеченными как несохранённые.
После остановки записи доступна кнопка скачивания аудио. Дата нового приёма учитывает местный часовой пояс.
